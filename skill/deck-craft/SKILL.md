# 汇报页面制作

基于《演说之禅》（Garr Reynolds）与《用图表说话》（基恩·泽拉兹尼）。

## 第一原则

**幻灯片是给人看的，不是给人读的。**

观众只有一份注意力。页面上字一多，他们就会低头读字，不再听你讲。这时候你站在那里就是多余的——不如直接发一份报告。

所以：**页面承载图与关键词，你的嘴承载解释。**

如果一页的内容让人必须读完才懂，那它不属于幻灯片，属于附录或报告。

## 页面字数上限

- 一页正文**不超过 60 个汉字**，超过就要拆页或移进备注
- 一个要点**一行**，不写解释句
- 表格单元格内不写完整句子，写短语
- 页面上不出现「因为…所以…」这类完整论证——那是你要说的话

检验：站在三米外看这一页，三秒内能抓到它在说什么吗？抓不到就要改。

## 每页标题写结论

和结构化汇报同一条规则，但在幻灯片上更重要——因为标题往往是观众唯一会认真读的一行。

| 弱 | 强 |
|---|---|
| 项目里程碑 | 各节点均按原计划完成 |
| 竞品数据采集 | 抓取结果入库前必须人工复核 |
| 用户资源池 | 跑一个项目，用户资产厚一层 |

## 一页一个意思

一页只讲一件事。如果一页里有两个并列的论点，拆成两页——页数多不是问题，一页讲不完才是问题。

判断方法：为这一页写一句话摘要，如果需要用「同时」「另外」「此外」才能写完，就该拆。

## 图表选型

先想清楚**你要表达哪种比较关系**，再决定用什么图。这是《用图表说话》最可操作的部分：

| 你要表达的关系 | 用什么图 | 例子 |
|---|---|---|
| 成分（占比） | 饼图 / 堆叠条 | 三个模块各占多少功能 |
| 项类比较（排序） | 条形图（横向） | 各品牌新品数量排名 |
| 时间序列（趋势） | 柱图（少量）/ 折线（大量） | 每月竞品新增数 |
| 频率分布 | 柱图 / 折线 | 用户参与次数分布 |
| 相关性 | 散点图 / 双向条形 | 重要性 × 满意度 |
| 时间与进度 | 甘特图 | 从立项到上线的节点 |
| 流程与依赖 | 流程图 / 泳道图 | 谁在什么阶段做什么 |

**图表标题也写观点**：写「竞品新品集中在三个品牌」，不写「品牌分布」。

**不要做的事**：3D 效果、无意义的渐变、图例放在远离数据的角落、一张图塞五个维度。

## 备注承载什么

从页面上删掉的内容不是扔掉，是移进演讲者备注。备注里写：

- 这一页要讲的完整逻辑，按讲的顺序
- 每个要点的展开说明
- 数字的口径与来源
- **被追问时怎么答**——这是备注里最值钱的部分

备注写得细一点没关系，只有你自己看。

## 投屏可读性

- 正文字号不小于 14px（按 1280×720 画布计），关键数字可以到 48px 以上
- 会议室灯光下浅底深字比深底浅字清晰
- 语义色（好 / 警告 / 严重）要和主题色分开，不要混用
- 截图必须能看清，看不清的截图不如不放——需要的话现场打开系统演示

## 页面类型配比

一份 15–20 分钟的汇报，建议：

- 封面 1 页
- 结论页 1 页（只有数字，字号放大）
- 背景 1–2 页
- 主体 8–12 页（每页一图或一组图）
- 收尾 1–2 页

**连续三页都是纯文字表格，说明这份材料该改成文档而不是幻灯片。**

## 反模式清单

遇到这些立刻改：

- 一页塞满要点，每个要点还带一行解释
- 标题是名词短语（「XX 管理」「XX 情况」）
- 表格超过 8 行或超过 5 列
- 同一页既有大段文字又有图，两边都看不清
- 图表没有标题，或标题只写了维度名
- 用截图代替说明，但截图缩得看不清
- 页面上写了完整的因果论证句

## 交付前自查

- [ ] 每页标题是结论，不是主题
- [ ] 每页正文不超过 60 字
- [ ] 每页只讲一件事
- [ ] 每张图的类型匹配它要表达的比较关系
- [ ] 图表标题写了观点
- [ ] 删掉的解释都进了备注
- [ ] 三米外能看清所有文字
- [ ] 没有连续三页纯文字
